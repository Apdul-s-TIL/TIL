# Containers

## Container란?

- 애플리케이션 실행에 필요한 런타임 의존성(Dependencies)과 함께 패키징하는 기술

### 일관된 재현성

- 실행하는 모든 컨테이너는 동일하게 반복 가능함
- 의존성이 패키지에 모두 포함되어 표준화되었기 때문에, 어떤 환경에서 실행하더라도 항상 같은 방식으로 동작한다는 것을 의미함

### 인프라와의 디커플링(분리)

- 컨테이너는 애플리케이션을 기본 호스트 인프라에서 분리함
    - 덕분에 다양한 클라우드 환경이나 OS 환경에서 훨씬 쉽게 배포 가능

### Kubernetes에서 Container의 작동

- 쿠버네티스 클러스터의 각 Node는 자신에게 할당된 Pod을 구성하는 컨테이너들을 실행함
- 하나의 Pod 안에 속한 컨테이너들은 동일한 노드에 함께 배치되고 함께 스케줄링 되어 실행됨

## Container Images

- 컨테이너 이미지는 애플리케이션을 실행하는 데 필요한 모든 것을 포함하고 있는 바로 실행 가능한(ready-to-run) 소프트웨어 패키지임
    - 여기에는 다음과 같은 것들이 포함됨
        - 코드
        - 필수 런타임
        - 애플리케이션 및 시스템 라이브러리 
        - 주요 설정의 기본값 등

### 상태가 없고(Stateless) 변경 불가능(Immutable)

- 컨테이너는 기본적으로 이 특성을 따르도록 설계됨
    - 즉, 이미 실행 중인 컨테이너의 코드를 직접 수정해서는 안됨
- 컨테이너화된 애플리케이션에 변경 사항을 적용하고 싶다면, 변경 사항이 반영된 새로운 이미지를 빌드한 다음, 이 업데이트된 이미지로 컨테이너를 새로 생성하는 것이 올바른 프로세스임

## Container Runtimes

- 쿠버네티스가 컨테이너를 효과적으로 실행할 수 있도록 돕는 핵심 컴포넌트
- 쿠버네티스 환경 내에서 컨테이너의 실행과 라이프사이클(생명주기)을 관리하는 역할을 담당함

### 지원하는 런타임

- 쿠버네티스는 `containerd`, `CRI-O` 를 비롯하여 쿠버네티스 CRI(Container Runtime Interface)를 구현한 모든 컨테이너 런타임을 지원함

### 기본 작동 및 확장

- 일반적으로는 클러스터가 Pod의 기본 컨테이너 런타임을 자동으로 선택하도록 두면 됨
- 만약 클러스터 내에서 두 개 이상의 컨테이너 런타임을 사용해야 한다면, Pod에 런타임클래스(RuntimeClass)를 지정하여 쿠버네티스가 특정 컨테이너 런타임으로 해당 컨테이너를 실행하도록 강제할 수 있음

### 다양한 설정 적용

- 런타임클래스를 사용하면 하나의 컨테이너 런타임을 사용하여 복수의 파드들을 각자 다른 설정으로 실행할 수 있음
