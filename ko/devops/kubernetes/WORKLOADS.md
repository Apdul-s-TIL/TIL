# Workloads

## Workload란?

- 워크로드는 쿠버네티스 위에서 실행되는 애플리케이션을 의미함
- 쿠버네티스에서는 워크로드를 일련의 파드(Pod) 내부에서 실행함
    - 워크로드가 단일 컴포넌트이든 서로 협력하는 여러 컴포넌트이든 관계 없음
- 쿠버네티스에서 파드는 클러스터에서 실행 중인 하나 이상의 컨테이너 집합을 나타냄

### Pod의 생명주기(Lifecycle)

- 쿠버네티스 파드는 정의된 생명주기를 가짐
    - 예를 들어, 파드가 실행 중인 노드(Node)에 심각한 오류가 발생하면 해당 노도의 모든 파드가 실패(Fail)함
        - 쿠버네티스는 이러한 수준의 장애를 최종(final)으로 취급함
        - 즉, 이후에 노드가 다시 정상 상태로 회복되더라도, 장애를 복구하려면 새로운 파드를 생성해야 함

### 워크로드 리소스의 필요성

- 다행히 사용자가 각 파드를 직접 관리할 필요는 없음
    - 대신 사용자를 대신해 파드 집합을 관리해주는 워크로드 리소스를 사용할 수 있음
- 이 리소스들은 사용자가 지정한 상태(Desired State)에 맞춰 올바른 종류의 파드가 적절한 개수로 실행되도록 컨트롤러(Controllers)를 구성함

## 내장 워크로드 리소스 종류

- 쿠버네티스는 다음과 같은 여러 내장(Built-in) 워크로드 리소스를 제공함

### Deployment 및 ReplicaSet

- 클러스터에서 상태가 없는(Stateless) 애플리케이션 워크로드를 관리하는 데 적합한 워크로드
- Deployment 내의 모든 파드는 서로 교체 가능하며, 필요할 때 언제든 대체될 수 있음

### StatefulSet

- 어떤 방식으로든 상태를 추적하는 하나 이상의 파드를 동작하게 해 주는 워크로드
    - 예를 들어, 워크로드가 데이터를 지속적으로 지록해야 하는 경우, 각 파드를 PersistentVolume과 매칭하는 StatefulSet을 실행할 수 있음
- StatefulSet 내부 팟에서 실행되는 코드는 전체적인 회복력(Resilience) 향상을 위해서 동일한 StatefulSet 내의 다른 파드로 데이터를 복제할 수 있음

### DaemonSet

- 노드 로컬 환경에 필요한 기능을 제공하는 파드를 정의하는 워크로드
- DaemonSet에 지정된 조건과 일치하는 노드가 클러스터에 추가될 때마다, 컨트롤 플레인은 해당 노드에 DaemonSet용 파드를 스케줄링 함
- DaemonSet의 각 팟은 기존 Unix/POSIX 서버의 시스템 데몬과 유사한 작업을 수행함
- DaemonSet은 클러스터 네트워킹을 실행하는 플로그인처럼 클러스터 운영에 필수적일 수도 있고, 노드 관리를 돕거나 컨테이너 플랫폼의 기능을 향상시키는 선택적 기능을 제공할 수도 있음

### Job 및 CronJob

- 실행 완료 후 종료되는 태스크를 정의하는 각각 서로 다른 방법을 제공하는 워크로드들임
    - Job은 단 한 번만 실행되어 끝까지 완료되는 작업을 정의할 때 사용함
    - CronJob은 일정(Schedule)에 따라 동일한 Job을 여러 번 반복해서 실행할 때 사용함

### CRD(Custom Resource, Definition)

- 쿠버네티스 핵심 기능에 없는 특정 동작이 필요하다면 CRD를 사용하여 서드파티 워크로드 리소스를 추가할 수 있음
    - 더 넓은 쿠버네티스 에코시스템 내에서는 추가적인 동작을 제공하는 서드파티 워크로드 리소스를 찾을 수 있음
    - 예를 들어 사용자 애플리케이션을 위해 일련의 파드를 실행하되 모든 파드가 사용 가능한 상태가 될 때까지 작업을 중단하고 싶다면(아마도 높은 분산 처리를 하는 상황 같은), 사용자는 해당 기능을 제공하는 확장을 구현하거나 설치할 수 있음

## 워크로드 배치(Workload placement)

- Deployment나 Job 같은 표준 워크로드 리소스가 파드의 생명주기를 관리하지만, 여러 파드 그룹을 하나의 단일 단위로 취급해야 하는 복잡한 스케줄링 요구사항이 있을 수 있음
- Workload API를 사용하면 PodGroupTemplates를 정의하여 파드를 그룹화하고, 갱 스케줄링(Gang Scheduling)과 같은 고급 스케줄링 정책을 적용할 수 있음
    - 이 기능은 "전부 아니면 전무(All-or-nothing)" 배치가 필요한 배치 처리 및 머신러닝 워크로드에 특히 유용함
