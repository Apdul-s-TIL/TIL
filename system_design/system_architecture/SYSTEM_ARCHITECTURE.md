# System Architecture

## Introduction

회사 서비스가 모놀리식 아키텍처에서 마이크로서비스 아키텍처로 전환 중에 있습니다. 개인적으로 그 전환 과정에 참여하고 있음에도 정확히 마이크로서비스 아키텍처가 무엇이고, 어디까지 마이크로서비스로 분리해야 하는지 애매모호한 부분이 많았습니다. 이 문서는 위 궁금증을 해소하고, 안정적인 시스템을 구축하고 싶은 개발자가 공부한 내용을 정리한 문서입니다.

## System Architecture란?

- 시스템 아키텍처란 시스템의 구조, 행위, 뷰를 정의하는 개념적 모델
    - 시스템의 각 컴포넌트에는 무엇이 있고, 어떻게 상호작용하는지, 그리고 어떻게 데이터가 교환되는지를 설명함
- 시스템 아키텍처는 하드웨어, 소프트웨어, 네트워크 등 시스템을 구성하는 모든 요소와 그 관계를 포함함
    - 하드웨어 플랫폼: 서버, 저장 장치 및 네트워크 인프라
    - 소프트웨어 플랫폼: 하드웨어에서 실행되는 운영 체제, 애플리케이션 서버 및 기타 소프트웨어 구성 요소
    - 시스템 인터페이스: 시스템과 상호 작용하는 데 사용되는 API 및 사용자 인터페이스가 포함
    - 시스템 구조: 시스템의 전반적인 구성으로, 다양한 구성 요소 간의 관계 및 상호 작용 방식을 포함
    - 보안: 악의적인 공격과 무단 접근으로부터 시스템과 사용자를 보호하기 위함

## System Architecture의 중요성

- 시스템 아키텍처는 시스템의 기획, 제작, 테스트 및 구현에 참여하는 모든 사람에게 명확한 설계 목표를 전달함
    - 이를 통해 오해를 방지하고, 요류 및 설계 목표 미달의 위험을 최소화할 수 있음
    - 모든 이해관계자의 요구사항이 충족되었음을 문서화하고, 설계 의도의 타당성을 검증하는 기준을 제공함
    - 팀 간 협업을 지원하여 위험을 더욱 줄여줌
- 시스템 아키텍처는 시스템의 확장성과 유연성을 보장함
    - 시스템이 미래의 요구 사항을 수용할 수 있도록 함
- 시스템 아키텍처는 시스템의 보안을 강화하는 데 중요한 역할을 함
- 시스템 아키텍처는 다양한 컴포넌트 간의 효율적인 통신을 가능하게 함

## System Architecture 예시

- Monolithic Architecture
    - 시스템의 모든 구성 요소가 긴밀하게 결합되어 단일 서버에서 실행되는 전통적인 접근 방식
    - 컴포넌트들은 공통 코드 베이스를 공유함
- [MicroService Architecture](./micro_service_acrhitecture/MICRO_SERVICE_ARCHITECTURE.md)
    - 시스템을 네트워크를 통해 서로 통신하는 작고 독립적인 서비스들의 집합으로 나눔
    - 각 서비스는 특정 작업을 담당하며 독립적으로 개발, 배포 및 확장이 가능함
        - 이는 유연성과 확장성을 높여주지만, 시버스 간의 상호 작용을 관리하는 데 있어 더 복잡한 측면도 요구함
- [Event-driven Architecture](./event_driven_architecture/EVENT_DRIVEN_ARCHITECTURE.md)
    - 시스템의 여러 컴포넌트 간에 이벤트를 주고받는다는 개념에 기반함
    - 이벤트는 한 구성 요소에서 생성되고, 해당 이벤트에 관심 있는 다른 컴포넌트에서 소비됨
        - 이를 통해 비동기적이고, 결합도가 낮은 시스템을 구현할 수 있음
- Serverless Architecture
    - 서버 프로비저닝 및 관리에 대한 필요성을 없애고, 서버에 대해 신경 쓰지 않고 코드를 실행할 수 있도록 함
    - 클라우드 제공업체가 인프라 확장 및 유지 관리를 담당하므로 개발자는 코드 작성에만 집중할 수 있음
